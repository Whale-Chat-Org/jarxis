## Providers naming and compatibility

REQ-PROVIDERS-01 is implemented across modules, components, canonical routes, Prisma model identifiers, worker entry/command/service, tests and active documentation. `docs/providers.md` documents the upgrade path.

Legacy admin bookmarks redirect with their query parameters. Legacy management API paths re-export the canonical guarded handlers. `ML_ENCRYPTION_KEY`, `pnpm ml:worker` and the optional legacy compose worker remain compatibility aliases. Conflicting nonempty encryption variables fail closed. Ciphertext format, connection IDs/AAD, physical SQL tables, endpoint-derived public model IDs, `jml_` gateway keys, lock hashes and Redis namespaces are retained. New events use `providers:*`; historical `ml:*` and dotted role actions remain interpretable through `audit-actions.ts` without rewriting history.

Crypto, model-ID, compatibility-route, audit, discovery and worker regressions cover these contracts. The migration narrows supported provider kinds without renaming or recreating provider tables.
