# Git rules

## Trunk-based workflow

- main is the trunk; keep it deployable. No long-lived develop branch.
- Before feature/fix work, inspect the branch and working tree, then create or switch to a suitable short-lived branch based on main: feature/<slug>, fix/<slug>, or chore/<slug>.
- Never perform or commit feature/fix work directly on main. Preserve in-progress work; do not switch a shared checkout out from under another agent.
- If no Git repository exists, do not initialize it or commit without an explicit user request. Report that branching is unavailable; this is never an exception permitting work on main.
- If branch changes are prohibited, honor that restriction and pause feature/fix work when the branch requirement cannot be met. This scoped documentation setup must not initialize Git or change branches.

## Commits and review

- Do not automatically commit, push or open a PR/MR. Each requires an explicit user request.
- Merge into main through a reviewed PR/MR with passing applicable checks: lint, typecheck, unit tests and relevant isolated integration/end-to-end tests. Do not bypass failures or directly push feature/fix work to main.
- Commit messages and PR/MR titles/descriptions must not contain AI attribution: no AI Co-authored-by trailers or Generated by Claude/Codex text.
- Preserve legitimate human attribution, including human Co-authored-by trailers.

## Preserve existing work

- Other agents may be active. Inspect status/diffs before changing Git state and preserve unrelated staged, unstaged and untracked work.
- No destructive resets, git clean, force-push or history rewriting. Do not discard, stash, amend or delete another agent's work to make the tree clean.
- Preserve concurrent work in place. Never automatically stash it; any relocation requires coordination. Resolve branch ownership conflicts without overwriting work.
